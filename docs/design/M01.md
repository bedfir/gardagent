# M01: Restart diagnostics and deterministic synchronization

Problem: restart failures lose their causes, accounting invariants are not all checked,
and several tests depend on elapsed time rather than observable progress.

Decision: extract pure restart classification and invariant evaluation helpers, covered by
network-free tests. Capture HTTP status and gateway error code independently from transport
failures. After workers drain, inspect the restart agent's raw PostgreSQL reservations and
all-day spend with read-only queries through the existing local Docker socket. Compare spend
against ledger costs for this newly created agent, avoiding UTC rollover ambiguity. Include
structured diagnostics in the result file and fail closed on observation errors.
Use observable state polling with event-loop yields for test synchronization; retain bounded
timeouts as failure deadlines rather than success conditions.

Alternatives rejected: admin reservation totals hide expired rows; current-day totals lose
admissions across midnight; fixed sleeps cannot prove completion. No runtime dependencies.

Compatibility: no gateway, schema, ledger hashing, or budget behavior changes. Historical
validation errors cannot be recovered. The harness requires psql in the PostgreSQL container
and its standard POSTGRES_USER/POSTGRES_DB configuration.

The MCP approval tests now explicitly start injection before waiting for pending
approval state. Other short synchronization sleeps were replaced by state polling,
stream-reader demand, or completion of the actual abandoned write promise.

Review revision: isolate each MCP migration fixture with a random schema, await its
creation before migration, and exercise two fixtures concurrently. No other test
file references ga_mcp, so a cross-file collision was not established; the fixed
schema nevertheless allowed overlapping test processes to destroy each other's
state. Each fixture now drops only its own schema, including on assertion failure.
The assertions still exercise adoption and repeated migration of populated data.

Restart requests have a 120-second client deadline so stalled transport requests
produce timeout diagnostics. The post-worker drain is two seconds, shorter than
the default reservation TTL (120-second upstream timeout plus 30-second margin).
The reservation assertion intentionally counts even unexpired rows: any remaining
row fails the strict cleanup criterion. A failure during the TTL can therefore
indicate pending cleanup rather than a permanently orphaned reservation; the
harness does not claim TTL expiry has elapsed or delete rows to make the check pass.
State polling uses a bounded 10-ms backoff to avoid busy event-loop spinning;
success still requires observing the requested state, never elapsed time.
