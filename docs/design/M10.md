# M10 — Optional Anthropic verification

## Problem

Synthetic endpoint tests establish format handling, not verification against the provider. Cost assertions must cover the actual usage mapping and rounding without a network dependency.

## Decision

Keep production arithmetic unchanged. Add hand-built public-format fixtures inline in anthropic.test.ts with exact micro-USD assertions. Input, cache creation and cache read counts share the configured input rate; output uses the output rate. Nested cache breakdowns and unrelated metadata are ignored.

A standalone tools/anthropic harness loads built gateway modules only after explicit opt-in and a CI refusal. A human supplies a key, model and input/output rates at runtime. It starts an authenticated gateway with MemoryStore, makes one plain and one streaming call to the fixed real provider endpoint, captures upstream bytes in memory, compares relay bytes, reconstructs usage independently and checks ledger cost and spend. Nothing is persisted. This tests the gateway path, not PostgreSQL durability or provider billing rates.

Response completion can precede streaming settlement and journaling. Before asserting accounting, poll both the expected ledger count and cumulative spend together with a three-second deadline and short intervals. Retain exact row and amount assertions after readiness; a timeout fails through the existing redacted error path. A fixed delay would remain dependent on scheduling and is rejected.

## Alternatives rejected

No live-provider test in the normal test suite: accidental execution and unavailable credentials must never affect the gate. No new SDK or dependency is needed. No separate cache rates or schema change: those would change accounting beyond M10.

## Compatibility impact

No runtime or schema change. Documentation labels Anthropic format-compatible, not yet verified against the provider. Only a human may run the harness and record a scoped result; no result is claimed here.
