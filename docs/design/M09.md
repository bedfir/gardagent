# M09 — Per-agent rate limiting

Problem: admission has no per-agent throughput or concurrency bounds.

Decision: optional positive integer requestsPerMinute and maxConcurrentRequests policy fields (zero means unlimited). Store them in nullable columns through migration 4; omit unlimited fields from policy canonicalization to preserve historical revision identifiers. Use a single-instance, process-local rolling 60-second admission window and active-call counter shared by all endpoints on the same application. Syntactically valid MCP messages and model admissions count even when a later policy or budget check refuses them. Acquire synchronously before budget work. Denials have zero cost and no reservation. Observe admissions still count and record an observed reason. Release concurrency on response finish or close, including errors and disconnected streams. Retry-After is integer seconds rounded up until the oldest minute-window admission expires; concurrency-only refusal uses 1 second as a retry hint since completion time is unknown.

Rejected: database counters and distributed coordination, which are outside the single-instance scope; fixed windows, which allow a double burst at the boundary.

Compatibility: absent or zero limits preserve unlimited behavior and old policy hashes. Counters and admission history are lost on restart; policy changes keep existing live counters and recent admission history. No ledger hash format changes.

Configuration through POST/PATCH /admin/agents uses requestsPerMinute and maxConcurrentRequests, integers from 0 through 2147483647. GET exposes zero for absent limits. The same agent shares limits across OpenAI, Anthropic and MCP. MCP request refusals use JSON-RPC error -32004 with retryAfter data; notification refusals have HTTP 429 with an empty body (no JSON-RPC response). Syntactically valid MCP messages count before method and tool policy checks; waiting for an approval holds a slot. Locally handled ping requests also count.
