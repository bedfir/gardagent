# M12 — Local first run and examples

## Problem

The first run requires a provider key and the repository has no runnable SDK or MCP examples.

## Decision

Add an isolated Compose file with a `local` profile: PostgreSQL, Ollama, a one-shot model download, the gateway, and a small example fixture. Bind only the gateway to host loopback. Generate the bootstrap token in the user's shell; use a clearly fake upstream key because configuration requires a nonempty value. Keep enforcement and agent authentication on. Use a small CPU model with persistent weights and explicit zero local accounting rates.

Provide Python SDK examples (no TypeScript build changes) and a standard-library MCP client and fixture. The fixture also returns a synthetic Anthropic response: it demonstrates SDK routing and governance, not real provider compatibility. The MCP write changes only fixture memory and requires a separate administrator decision.

Add static Vitest checks over documented routes and environment names against route registrations and configuration source, plus executable example command checks. Delegate the changelog sentence as a small writing task to OpenCode via the runner.

## Alternatives rejected

A hosted provider violates the keyless first-run requirement. Disabling gateway authentication hides the identity workflow. Adding SDK dependencies to the workspace increases the release surface; Python examples use their own virtual environments instead.

## Compatibility

No gateway, schema, ledger or authentication changes. Existing Compose deployments are unchanged. Local downloads and build time depend on hardware and network; under ten minutes is an unmeasured target. The fixture is for demonstration only and loses state on restart.
