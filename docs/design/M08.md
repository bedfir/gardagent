# M08: complete MCP governance

## Problem
The proxy forwards all non-tool traffic and all upstream events without policy or proof.

## Decision
Use explicit request, notification and server notification allow-lists with default refusal. Record every admitted non-tool message and denial, retaining argument-only hashes for tools and approvals. Answer ping locally. Reject unsupported HTTP transports explicitly. Filter tools/list results in JSON and SSE; observe mode retains the original listing and records the policy difference. Inspect both JSON responses and complete SSE events; suppress server requests and unknown notifications in enforce mode and record each refusal separately. Observe mode relays these messages with an observed denial row. Malformed framing remains refused in both modes.

## Alternatives rejected
Default forwarding cannot establish exhaustive governance. Disabling streaming would break existing governed tool responses. Relying solely on the parent stream hash would conceal individual refused server messages.

## Compatibility impact
Non-tool pass-through is intentionally replaced. Existing tool admission, approval hashes, read/write classification and historical ledger verification remain unchanged. Non-tool rows use server/- without a read/write suffix. GET and DELETE return 405. No schema or dependency changes.
