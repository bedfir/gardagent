# M05: mandate attribution

## Problem

A shared administration credential cannot distinguish decision makers. Mutable agent policy cannot explain the limits used by an earlier admission. Approval decisions lack a durable ledger correlation.

## Decision

Keep bootstrap authentication and add individually revocable, hashed operator credentials. Only bootstrap manages operators, as specified by the mandate contract. Carry authenticated operator ids per request, never in shared mutable state. Persist immutable canonical policy snapshots by content hash. Resolve the snapshot from the admission agent value once; carry its identifier through approval waiting and completion. Add nullable metadata without rewriting historical ledger entries. Store decisions and their ledger evidence atomically, and likewise operator and policy mutations.

Use sorted, unique policy lists; names and credentials are excluded. Global enforcement mode and server tool classification remain configuration outside the agent revision, explicitly documented. Existing agents obtain snapshots during migration; historical ledger fields stay absent.

## Alternatives rejected

Labels as identity are mutable and ambiguous. Resolving policy after approval attributes an action to limits that did not govern admission. Plaintext credentials or credential hashes in the ledger would expose authentication material. Updating old ledger rows invalidates historical proofs.

## Compatibility

New metadata is optional for historical records. Budget amounts, admission day, settlement semantics and legacy hashes stay unchanged. Token possession establishes credential possession, never human identity. No dependencies are required.

## Verification and delegation

Regression cases exercise both storage implementations: changed policy during approval, distinct deciding operators,
revocation, credential disclosure, stable canonical snapshots, and ledger-failure rollback. Migration checks retain
legacy row equality, hashes, spend and relation identity checks, adding snapshot immutability. Historical contract
fixtures remain unchanged; expected API shapes explicitly include the M05 additions. Node, pnpm and Docker execution
is reserved for the runner. OpenCode task 01 is a one-file documentation proofread; the reviewer must inspect its
result after the runner applies it.

## Gate follow-up: outage instrumentation

Agent creation now writes its audit row inside the atomic store operation rather than calling public
`appendLedger`. The frozen-store test double must observe that audited operation as a ledger write too.
Keep the exact write-count assertion and verify the persisted creation row before freezing: the subsequent
stream must still spool its proof without attempting another database append. No production transaction
boundary or outage behavior changes are needed.
