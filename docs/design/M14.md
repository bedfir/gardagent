# M14 — v1 readiness

## Problem

Earlier mission documentation mixes historical observations, implemented behavior and
unverified release goals. Operators need an actionable 0.3.0 upgrade and restore
procedure and an evidence inventory before any release decision.

## Decision

Reconcile every document under docs/ and both root READMEs against local source
and tests. Preserve dated validation results as history, explicitly distinguishing
them from current guarantees. Consolidate Unreleased with breaking changes first.
Describe backup, quiescence, spool preservation, forward migrations and restore to
an isolated pre-upgrade database; do not prescribe down migrations. Enumerate all
eleven exit criteria with source evidence and remaining execution gaps. Leave
provider verification, publication and independent-user validation to humans.

Check workspace manifests against lockfile importers. The requested verifier
importer already exists in this checkout; preserve it and report this fact rather
than introducing an artificial lockfile change.

## Alternatives rejected

A blanket readiness claim cannot substitute for runner or human results. Rewriting
historical measurements would erase evidence. Running an older binary against a
migrated database is not a rollback procedure.

## Compatibility impact

Documentation only; no version, runtime, schema, dependency or stored data changes.
Node, pnpm and Docker checks remain the runner's responsibility. Delegate one
mechanical documentation-index task through the runner; its final diff needs review.

## Inspection findings

MCP rate-limited requests currently return HTTP 200 with JSON-RPC -32004;
model requests and MCP notifications return HTTP 429. Record this as an unmet
part of exit criterion 3 rather than changing protocol code in this mission.
The deployment restore helper does not enable psql ON_ERROR_STOP or restore the
spool/executable; prescribe an isolated restore with fatal SQL errors and exact
recovery-set matching. Static link/evidence/importer checks and diff whitespace
checks passed; execution and the delegated index diff remain runner/reviewer work.
