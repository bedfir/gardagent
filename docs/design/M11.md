# M11 — Console browser tests

## Problem

Component and HTTP tests do not exercise the built console in a browser. Login,
forms, navigation, approval decisions and translated labels need coverage together.

## Decision

Run Playwright Chromium against the built console served by a real Fastify gateway
on an ephemeral loopback port. Each test owns a fresh MemoryStore and browser
context. Only the upstream adapter is fake; admin authentication, governance,
approval polling, ledger writes and verification use production code. Approval
fixtures originate in real governed calls, not inserted database records. Wait on
observable state and responses, with no fixed sleeps. Build before test discovery.
Pin Playwright and its official Noble image to the same version. CI runs the root
script inside that image and preserves failure artifacts. No provider credentials,
external requests or database service are needed.

## Runner handoff

Earlier attempts reported a container bootstrap failure (`pnpm: not found`) before
browser execution. Provision pnpm 10.28.0 inside the official browser image before
invoking `pnpm test:e2e`, and fail immediately if provisioning fails. CI already
uses `pnpm/action-setup` for this step. The external runner is outside this
mission's editable scope; repository package scripts cannot repair executable
lookup before they start.

The current checkout includes the pinned `@playwright/test@1.56.1` manifest and
lockfile entries. Retain the matching dependency request for the runner's handoff;
do not edit the lockfile manually. Browser acceptance still requires a successful
runner result. Static inspection cannot establish that Chromium passes.

## Alternatives rejected

A Vite development server would miss production asset paths and gateway serving.
Mocking admin HTTP responses would miss integration defects. PostgreSQL would add
setup cost without improving browser coverage; existing storage tests cover it.
Running all browsers is deferred: this mission establishes Chromium coverage.

## Compatibility impact

No API, database, ledger or stored-data changes. Existing 0.3.0 data and hashes are
unaffected. The new development dependency is requested through the runner. Console
changes will be made only for demonstrated defects; execution belongs to the runner.

## Browser gate follow-up: ledger selector lookup

The runner passed installation, type checking, 829 tests and the build, then
passed three browser tests. The ledger test timed out at the first exact
`getByLabel("Agent")` lookup. Its failure snapshot contains the search form,
combobox named Agent, and Alpha/Beta options. The wrapping HTML label includes
option text in Playwright's label lookup; an exact label-text match therefore
cannot find this control even though its accessible name is Agent.

Use exact combobox role/name locators for the three ledger selectors, including
the selection restored after reload. Assert the selected agent ID before continuing.
Keep every filter, row, reload and integrity assertion, with the same timeout and
no retries or sleeps. Do not change production markup merely to accommodate a
label-text locator: the browser snapshot already exposes the expected control
roles and accessible names. This correction changes only test targeting and has
no compatibility impact. A new runner browser result is still required.
